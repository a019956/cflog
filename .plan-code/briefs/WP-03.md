# WP-03 — Pipeline: polite crawler + platform detection  (owner: @backend · implemented by Claude)

## Goal
Given a café's website, fetch a few pages politely and return them with content hashes and the detected e-commerce platform.

## Context (02 § Crawler policy, § Platform detection)
UA `CoffeeLogBot/0.1 (+CRAWLER_CONTACT_URL)`. Obey robots.txt (RFC 9309: 4xx = allow, 5xx/unreachable = disallow; Crawl-delay honoured, capped at 30 s). ≤1 req/2 s per host. 8 hosts in parallel. ≤6 pages per site (robots.txt not counted). 15 s timeout, 2 retries with backoff on network errors, 429 and 5xx. Pages: home, then store JSON (Shopify `/products.json`, Woo Store API), then up to the remaining budget of same-site links matching coffee/menu/shop (PDF menus included). sha256 of cleaned text.

## Scope
In: `pipeline/src/crawl/**`, `pipeline/test/crawl.test.ts`, deps `robots-parser`, `cheerio`. Out: extraction and publishing.

## Acceptance criteria
1. `crawlSite` returns `no-site` / `blocked-robots` / `error` / `ok` with platform and pages.
2. Per-host spacing and concurrency are enforced (tested with a virtual clock).
3. Link picking skips cart/account/login/policy/blog, other hosts and images; it ranks coffee > menu > pdf > shop.
4. Tests use an injected transport (no network).

## Verify with
`npm run typecheck && npm run lint && npm test -w @cflog/pipeline`
