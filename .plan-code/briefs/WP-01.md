# WP-01 — Shared types, vocabularies & filter logic  (owner: @backend · implemented by Claude)

## Goal
Everything the app and pipeline share lives in `packages/shared`: document types, vocabularies, the flavor-family taxonomy with a tasting-note dictionary, origin countries → continents, launch-city config, and the pure `applyFilters` / `sortCafes` functions.

## Context (from 02 Architecture)
- Types: `CafeSummary`, `Cafe` (embedded `beans[]` ≤200, `menu[]` ≤150), `Bean`, `MenuItem`, `CityDoc`, `CityIndexDoc`, `PipelineStateDoc`, `Filters`.
- Vocab: RoastLevel, Process, Kind, DataStatus, Platform, CrawlStatus, MenuCategory, BeanSource.
- FlavorFamilyId: fruity (+berry, dried-fruit, other-fruit, citrus), sour-fermented, green-vegetative, roasted, spices, nutty-cocoa (+nutty, cocoa), sweet (+brown-sugar, vanilla), floral (+tea, floral), other.
- Filter semantics: OR within a dimension, AND across; a family id matches its sub-ids; any bean dimension (roast, process, origin, flavor, variety, decaf) excludes cafés whose `dataStatus !== 'beans'`. Café-level matching. `kind: 'both'` matches a Roaster or a Café filter.
- Sort: dataStatus tier (beans > menu-only > none), then distance if a user location is given, else name.

## Scope
In: `packages/shared/src/**`, `packages/shared/test/**`. Out: app and pipeline code.

## Acceptance criteria
1. Types match 02 § Data model.
2. `noteDictionary` has ≥300 entries, all mapping to valid FlavorFamilyIds. `mapTastingNote()` handles case, accents, punctuation, plurals and multi-word notes (e.g. "Jammy Blackberry" → fruity/berry; "cocoa nib" → nutty-cocoa/cocoa).
3. `countryFromName()` maps common origin names and regions (e.g. "Sumatra" → ID, "Yunnan" → CN) to ISO codes; `continentOf()` covers every mapped country.
4. `applyFilters` / `sortCafes` / `beanMatchesFilters` / `countActiveFilters` / `nearestCity` follow the semantics above.
5. ≥25 Vitest cases; filtering 1,000 cafés takes < 50 ms.

## Verify with
`npm run typecheck && npm run lint && npm test -w @cflog/shared`
